Updates

A fleet release is one signed manifest naming every package of a version. A rollout updates the coordinator first, then the canary, early and broad rings: a few nodes at a time, each inside its update window, baking before the next ring, halting (and rolling back) when installs fail. Each node installs the whole package through its root update runner and goes back to the previous one by itself if the new version does not confirm. No node ever runs a release newer than the coordinator.
